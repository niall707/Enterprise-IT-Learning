# Learning Roadmap

**Goal:** Develop demonstrable skills relevant to RHEL L2 systems administration, enterprise automation and IT operations.

## Phase 1 — Explore (seven-course starter programme)

Complete one selected course in each subject before committing to several long paths at once.

| Week | Stream | Starter course | Approx. video time | Status |
|---|---|---|---:|---|
| 1 | RHEL | RHCSA: Operating Running Systems | 1h 50m | Not started |
| 2 | Ansible | Ansible for Enterprise Automation | 2h 16m | Not started |
| 3 | Monitoring | SRE: Monitoring and Observability | 2h 17m | Not started |
| 4 | ServiceNow | Reporting and Dashboards Using Data-driven Insights | 1h 33m | Not started |
| 5 | UrbanCode / CI/CD | DevOps Foundations: CI/CD | 1h | Not started |
| 6 | Confluence | Confluence Foundations | 55m | Not started |
| 7 | AI | Integrating AI Agents with ServiceNow | 1h 30m | Not started |

**Total estimated viewing time:** 11h 21m, excluding practical labs. Weeks are suggested **sequence**, not calendar commitments. Full course links and alternatives: [Pluralsight plan](learning-plans/pluralsight-enterprise-it-learning-plan.md).

## Phase 2 — Deepen (choose a primary track)

| Priority | Longer pathway | Target capability | Portfolio output |
|---:|---|---|---|
| 1 | RHCSA / RHEL (~20h path) | Confident Linux service, storage, security and fault analysis | Two validated Linux labs |
| 2 | Ansible (~19h path) | Write, troubleshoot and validate repeatable automation | One tested Ansible automation lab |
| 3 | Observability + ITSM (selected modules) | Connect signals to action and reporting | An alert-trend case study using synthetic data |
| 4 | CI/CD + knowledge management | Controlled releases and consistent procedures | Deployment runbook with validation/rollback |
| 5 | AI for IT Pros | Evaluate human-approved operations assistance | Synthetic-data AI triage design and risk review |

## Phase 3 — Demonstrate

Aim to publish evidence **only after testing**:

- [ ] Linux service troubleshooting lab — reproduced and independently verified
- [ ] Linux filesystem/storage lab — includes safe rollback or teardown
- [ ] Ansible inventory/service audit — idempotence and error handling documented
- [ ] Alert investigation — synthetic trend data, severity and proposed tuning
- [ ] Incident-to-resolution case study — clear decisions and verification
- [ ] CI/CD deployment runbook — approvals, checks, failures and rollback

## Review routine

1. Choose the next course or question.
2. Record what changed in your understanding.
3. Run an exercise on a lab system you control.
4. Attach **redacted evidence** and update the progress tracker.
5. Revisit the plan at the end of each phase to reprioritise.

> Time targets and course availability are estimates, not completion claims. Review course pages before scheduling.
